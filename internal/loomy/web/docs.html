loomy2api（Go 版）把 Loomy（讯飞）账号的模型额度转成一套本地自托管的 OpenAI / Anthropic 兼容 API：纯 Go 1.27 标准库、零第三方依赖、编译成单个二进制，自带多账号池、自动续期与 Web 控制面板。本页是编译进二进制的离线手册，装好后不联网也能查。

快速开始

1. 拿到二进制

从源码构建，或到项目的 Release 页下载对应平台的预编译包（linux/amd64、linux/arm64、darwin/amd64、darwin/arm64、windows/amd64、windows/arm64）：

go build -o loomy2api ./cmd/loomy2api        # Windows 上产物是 loomy2api.exe

二进制是静态链接的（CGO_ENABLED=0），目标机器不需要装 Go，也不需要任何 Python 运行时或第三方包。校验下载可以用 Release 附带的 SHA256SUMS.txt：

sha256sum -c SHA256SUMS.txt          # Linux / macOS
certutil -hashfile loomy2api.exe SHA256   # Windows

2. 首次运行

./loomy2api                 # 不带参数等价于 ./loomy2api serve，默认 http://127.0.0.1:17890

首次启动时若 config.json 不存在（默认 ./config.json，或 -c/--config 指定的路径），程序会先自动生成一份带注释的默认配置再继续加载 —— 所有子命令都是这个行为，所以第一次跑任何命令都会看到「已创建默认配置」。

优先级是 环境变量 > config.json > 内置默认值，配置里的相对路径相对 config.json 所在目录解析。默认配置模板编进二进制（内容同仓库里的 config.example.json），改模板要重新编译。

3. 添加第一个账号

./loomy2api add main --phone 13800000000 --password '你的密码'
./loomy2api accounts          # 确认 session 剩余天数与额度
./loomy2api serve             # http://127.0.0.1:17890，面板在 /panel

密码需要先在讯飞账号中心（网页或手机端）设置一次 —— 桌面客户端里没有「设置密码」入口。没有密码也能用，见下面的短信登录。添加成功后账号与 session 会写进 accounts.json（该文件已在 .gitignore 里）。

4. 常用命令

全局参数 -c/--config <path> 写在子命令之前；每个子命令都支持 --help。

命令作用
serve启动网关（--port 覆盖配置端口；不带子命令时默认就是它）
accounts / quota账号池状态 / 各账号积分
add / remove加账号 / 删账号（remove 无 -y 时会问一次）
login [name ...]强制重登并续期（缺省=全部）
sms / verify短信登录两步：发码 → 用验证码换 session
identity <name>查看设备标识（--rebind 换新设备并重登）
models / chat "prompt"列上游模型 / 单次对话自检

添加账号

三种方式任选，最后都落到同一个 accounts.json。

手机号 + 密码（推荐）

./loomy2api add main --phone 13800000000 --password '你的密码'

这是唯一能自动续期的形态：后台每隔 quota_refresh_minutes 巡检一次，session 剩余不足 session_renew_before_days（默认 3 天）就自动重登，账号池可以长期无人值守。

短信登录（没有密码时）

./loomy2api sms 13800000000                 # 发验证码，记下输出里的 msgid
./loomy2api verify main 13800000000 <验证码> <msgid>

两步都在同一台机器上执行、不要间隔太久；verify 成功后 session 同样写进 accounts.json。这种账号没有密码，14 天到期后需要重新走一遍（或先到账号中心设密码，再改成密码账号）。

导入客户端会话 / 手写 accounts.json

本机装了并登录了 Loomy 桌面客户端时，sessions_from_client: true（默认开）会自动把客户端的会话当作一个额外账号拾取进来，不需要手工干预。也可以直接写文件：

{
  "accounts": [
    { "name": "main",   "loginid": "13800000000", "password": "…", "enabled": true },
    { "name": "backup", "loginid": "13900000000", "password": "…", "enabled": true },
    { "name": "shared", "session": "<32 位 session>", "userid": "…", "expireAt": 0 }
  ]
}

只有 session 的账号无法自动续期（14 天后失效），适合临时借用；enabled: false 可以保留配置但暂时不参与路由。文件里可能有明文密码与绑定好的设备标识，注意权限：

chmod 600 accounts.json config.json

给网关加一层钥匙

{ "api_keys": ["sk-local-whatever"] }

之后再启动，客户端要带 Authorization: Bearer sk-local-whatever 或 x-api-key: sk-local-whatever。/health 始终公开，方便探活；面板页面本身也公开（好让你输入密钥），但面板的 /api/panel/* 全部需要密钥。面板改完 config.json 可以点「重载配置」热载，不必重启。

多账号池与路由

每个账号在 accounts.json 里带自己的 session、额度缓存与设备标识；请求在池内按策略挑号。

strategy行为
balance（默认）用可用积分最多的账号
round_robin按顺序轮着用
lru最久未用优先

失败处理：401/403 丢弃该账号的 session；402 / 额度耗尽 让账号冷却 cooldown_seconds 秒；两种情况都会自动换下一个账号重试，最多 max_retries 次。上游 5xx 不冷却账号。状态都能在 GET /v1/admin/accounts、GET /v1/points 与面板总览里看到。

设备标识

每个账号首次登录时生成一套自己的设备标识并绑定进 accounts.json（devid、ua、modelid、校园设备号），之后每次续期与请求都复用它，避免一个池子里所有账号都自报同一个 devid: web。

identity_mode行为
per_account（默认）每个账号独立的 devid（web-<16 hex>）与校园设备号；ua/modelid/version 保持真实客户端值
client逐字节对齐官方客户端（devid: web）

换标识：面板上点「换标识」，或 ./loomy2api identity main --rebind，或 POST /api/panel/accounts/identity 带 {"name": "main", "regenerate": true}。换完会立刻用新标识重登一次。提醒一句：这只能做账号隔离，改不了你的出口 IP。

API 用法

两种方言同时可用，路径与官方一致；模型 id 原样透传给上游，没有别名表（只去掉 provider/ 前缀）。

OpenAI 方言

curl http://127.0.0.1:17890/v1/chat/completions \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer not-needed' \
  -d '{"model": "deepseek-v4-flash-0731",
       "messages": [{"role": "user", "content": "hello"}]}'

加上 "stream": true 就是 SSE 流式（data: 帧，末尾 [DONE]）。Python SDK：

from openai import OpenAI

client = OpenAI(base_url="http://127.0.0.1:17890/v1", api_key="not-needed")
print(client.chat.completions.create(
    model="deepseek-v4-flash-0731",          # 见 GET /v1/models
    messages=[{"role": "user", "content": "hi"}],
).choices[0].message.content)

Anthropic 方言

curl http://127.0.0.1:17890/v1/messages \
  -H 'Content-Type: application/json' \
  -H 'x-api-key: not-needed' \
  -H 'anthropic-version: 2023-06-01' \
  -d '{"model": "deepseek-v4-flash-0731", "max_tokens": 256,
       "messages": [{"role": "user", "content": "hello"}]}'

thinking 块、tool use / tool result 都会被翻译。Claude Code 这类客户端注意 base URL 填裸 host（/v1/messages 挂在根上，和真 API 一样），不要带 /v1：

export ANTHROPIC_BASE_URL=http://127.0.0.1:17890
export ANTHROPIC_API_KEY=not-needed

端点一览

端点说明
POST /v1/chat/completionsOpenAI 兼容，流式 + 非流式
POST /v1/messagesAnthropic 兼容，流式 + 非流式
GET /v1/models上游模型目录
POST /v1/embeddings / POST /v1/images/generations透传上游
GET /v1/points各账号积分（按 userid 去重合计）
GET /health探活：状态、可用账号数、模型数
GET /panel（及 /）Web 控制面板
GET /api/panel/state · /logs · /models · /docs面板 JSON API（启用 api_keys 后需鉴权）

模型 id 的行为值得记一笔：上游对不认识的 id 不报错，而是静默回落到 deepseek-v4-flash-0731。所以拿到响应先看 model 字段，对不上就说明这个名字上游没有。

Web 面板

打开 http://127.0.0.1:17890/panel（裸 host 也是面板），六个页签：总览、添加账号、日志、模型、文档、接口速查。

  • 总览：每个账号的可用积分（余额 + 每日赠额）、session 剩余天数、请求与扣分计数、冷却状态、设备标识；行内按钮可续期 / 换标识 / 禁用启用 / 删除。
  • 添加账号：手机号 + 密码（添加后立即登录），或直接粘一个 session。
  • 日志：网关请求日志的实时尾部（模型、token、扣分、延迟），按行高亮错误与警告。
  • 模型：上游目录，带积分倍率、上下文长度、能力标签与搜索排序。
  • 文档：就是本页，内容编译在二进制里，不依赖外网。
  • 接口速查：一屏看完所有端点。

右上角还有「刷新额度」（强制重拉所有账号积分）、「重载配置」（热载 config.json）、自动刷新开关与明暗主题切换。启用了 api_keys 时页面会先弹一个密钥框，密钥存在浏览器 localStorage 里，「登出」只清本机。

部署

Linux（systemd）

把二进制放到 /opt/loomy2api/，和 config.json、accounts.json 放一起，然后：

[Unit]
Description=loomy2api gateway
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=loomy
WorkingDirectory=/opt/loomy2api
ExecStart=/opt/loomy2api/loomy2api serve
Restart=always
RestartSec=5
UMask=0077                     # accounts.json 里是明文密码
Environment=LOOMY_HOST=127.0.0.1

[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now loomy2api
journalctl -u loomy2api -f          # 跟日志

保存为 /etc/systemd/system/loomy2api.service；ExecStart 指向二进制本体，不需要解释器，也不需要 Environment=PATH 之类的东西。

Windows

计划任务（系统自带，不加软件）：写一个 start.cmd：

@echo off
cd /d D:\loomy2api
loomy2api.exe serve >> logs\console.log 2>&1
schtasks /create /tn loomy2api /sc onstart /rl highest /tr "D:\loomy2api\start.cmd" /f
schtasks /run /tn loomy2api

或者用 NSSM 装成真正的 Windows 服务（可自动重启、可看退出码）：

nssm install loomy2api "D:\loomy2api\loomy2api.exe" "serve"
nssm set loomy2api AppDirectory D:\loomy2api
nssm set loomy2api AppStdout D:\loomy2api\logs\service.log
nssm start loomy2api

Docker / Compose

docker build -t loomy2api .
docker run -d --name loomy2api -p 17890:17890 -v "$PWD/data:/data" loomy2api

镜像多阶段构建：golang:1.27 编译出静态二进制，alpine:3.21 只带二进制、CA 证书与时区。容器内固定 LOOMY_HOST=0.0.0.0、LOOMY_ACCOUNTS_FILE=/data/accounts.json、LOOMY_LOG_DIR=/data/logs，所以只要把 config.json、accounts.json 放进挂载到 /data 的目录即可。Compose 版本：

services:
  loomy2api:
    build: .
    container_name: loomy2api
    restart: unless-stopped
    ports: ["17890:17890"]
    volumes: ["./data:/data"]
mkdir -p data && cp accounts.example.json data/accounts.json   # 然后编辑它
docker compose up -d --build
docker compose logs -f

对外开放（可选，先读这段）

默认只绑 127.0.0.1，只有本机能访问。要共享给局域网或公网：

  • 先设好 api_keys —— 没有鉴权时，谁能连上端口谁就能花你账号的积分。
  • 再把 host 改成 0.0.0.0（或设环境变量 LOOMY_HOST=0.0.0.0）。
  • 公网就再加一层带 TLS 的反向代理，例如 Caddy：
api.example.com {
    reverse_proxy 127.0.0.1:17890
}

客户端这时用 https://api.example.com/v1 作为 base URL。更稳妥的做法是用 VPN / Tailscale / WireGuard 打通，而不是直接暴露公网 —— 网关自身没有限流。

升级与备份

单二进制的升级就是换文件 + 重启：

# 源码方式
git pull && go build -o loomy2api ./cmd/loomy2api && sudo systemctl restart loomy2api

# Release 方式
# 下载新平台的二进制覆盖旧文件，再重启服务

# systemd
sudo systemctl restart loomy2api
# Docker
docker compose up -d --build

Windows 计划任务要把任务先结束再启动（schtasks /end /tn loomy2api → 换文件 → schtasks /run /tn loomy2api），否则可执行文件被占用无法覆盖。NSSM 用 nssm restart loomy2api。

需要备份的就两个文件：

  • accounts.json —— 账号、session、（如果填了）明文密码，以及每个账号绑定的设备标识。丢了要重新登录并重新绑定。
  • config.json —— 你的设置。

两者都在 .gitignore 里。logs/ 是纯输出，可以随时删。没有数据库，没有 migration。
